# Руководство shapeledger

Сравнивайте наблюдаемую структуру JSONL при обновлении фикстур и выгрузок, не сохраняя примеры скалярных значений. [English](../README.md) · [简体中文](README.zh-CN.md) · [Deutsch](README.de.md)

## Запуск

Python 3.10+, только стандартная библиотека во время исполнения. Из корня репозитория:

```sh
python -m shapeledger profile examples/baseline.jsonl > /tmp/baseline.shape.json
python -m shapeledger profile examples/candidate.jsonl > /tmp/candidate.shape.json
python -m shapeledger compare /tmp/baseline.shape.json /tmp/candidate.shape.json
python -m shapeledger compare /tmp/baseline.shape.json /tmp/candidate.shape.json --fail-on added_type --fail-on removed_path --fail-on missing_increase
```

Последняя команда для этих примеров возвращает 1. `python -m pip install .` устанавливает команду `shapeledger`; сборке нужен setuptools, исполнению сторонние библиотеки не нужны. `profile -` читает stdin. Детерминированный JSON выводится в stdout. Перенаправляйте его в новый файл: оболочка может обнулить старый файл ещё до проверки входа. Вход полностью проверяется до начала вывода. Ошибка вывода может оставить неполный файл; при коде выхода 2 его следует отбросить.

## Формат и счётчики

Каждая строка должна содержать ровно одно строгое JSON-значение в UTF-8; корневой тип произвольный. Пустые строки, BOM, повторяющиеся ключи, NaN, Infinity, переполнение float и повреждённые записи отклоняются. Допускаются CRLF и последняя строка без перевода строки. Диагностика указывает номер неверной записи, не раскрывая её текст.

Профиль версии 1 содержит `version`, `records` и упорядоченный список `nodes`. Узел содержит `path`, `types`, `opportunities`, `array_items`. Различаются object, array, string, integer, number, boolean и null; `1` отличается от `1.0`. Типизированный путь: `[["key","users"],["items"],["key","name"]]`. Точки, косые черты, звёздочки, пустые ключи и буквальный ключ `items` не создают коллизий.

- Число возможностей у корня равно числу записей.
- Для дочернего ключа это число наблюдаемых объектов на родительском пути, а не всех записей или всех типов родителя.
- Для элемента массива это общее число элементов; каждый, включая null, наблюдается один раз.
- Число пропусков = возможности минус сумма счётчиков типов. Null означает присутствие, не пропуск.
- `array_items` суммирует длины массивов в узле. Пустой массив не создаёт узел элементов. Поля объектов внутри массивов используют только число таких объектов.
- Нет наблюдений — нет узла. Исчезновение родителя даёт удаление пути, а не вымышленную нулевую долю.

Ключи объектов и счётчики сохраняются и могут быть чувствительными, особенно динамические ключи. Это минимизация данных, не анонимизация. Скалярные значения временно разбираются в памяти, но не попадают в результат. Ошибки не содержат исходных строк или имён файлов.

## Сравнение и CI

Перед сравнением оба профиля строго проверяются. События: `added_path`, `removed_path`, `added_type`, `missing_increase`, `null_increase`. Для существующих путей доли сравниваются точно как рациональные числа и выводятся, например, как `1/3`. Доля null делится на возможности, не на число присутствий. Любое положительное увеличение даёт событие; настраиваемых числовых порогов в версии 0.1 нет. Удалённые типы не выводятся. Новые и удалённые пути дают только события пути, без дополнительных событий типов и долей.

Все события выводятся независимо от политики. Повторяйте `--fail-on KIND`, чтобы выбрать причины отказа CI. Без этого сравнение только информационное.

- Код 0: вход корректен, выбранные условия не сработали.
- Код 1: сработало хотя бы одно выбранное условие.
- Код 2: неверный вход/профиль, превышение лимита, ошибка I/O или аргументов.

## Ограничения

Потоковая обработка идёт по записям, а не токенам JSON. По умолчанию строка ограничена 1 MiB, включая перевод строки (`--max-line-bytes`), число узлов — 10 000 (`--max-nodes`), глубина пути — 64 (`--max-depth`, корень 0). Лимиты узлов и глубины можно только уменьшать. Все лимиты — положительные целые. Лимит строки должен быть меньше платформенного значения Python `sys.maxsize`, чтобы оставался один дополнительный байт для выявления слишком длинных записей; большие значения отклоняются до чтения записей. Память зависит от максимальной строки и множества путей. Элементы массивов объединяются, динамические ключи не нормализуются. Парсер Python может раньше отклонить слишком глубокую запись. Каждый файл профиля ограничен 32 MiB; проверяются поля, версия, пути, счётчики и родительские связи.

Профиль — наблюдение, не криптографическое свидетельство и не полный JSON Schema. Нет валидации схем, вывода распределений, объединения профилей, игнорирования полей или диапазонов чисел. Float разбирается стандартной библиотекой; точность значения не влияет на счётчики типов. Для вывода нужно место на диске. Заполненный диск или закрытый канал, включая ошибку сброса буфера, приводит к коду 2 и безопасной диагностике ошибки вывода. Это имеет приоритет над кодом 0 или 1 выбранных условий сравнения; успешный сброс буфера не гарантирует долговременное сохранение данных.

## Альтернативы и разработка

[GenSON](https://github.com/wolverdude/GenSON) создаёт и объединяет JSON Schema. [DataProfiler](https://github.com/capitalone/DataProfiler) предоставляет более широкое статистическое профилирование и анализ сущностей. Здесь акцент на счётчиках структуры, пропусках относительно родителя и явных событиях CI; проект не заменяет эти средства и не заявляет нового алгоритма вывода схем.

```sh
python -m unittest discover -s tests -v
python -m pip wheel --no-deps . -w dist
```

CI проверяет Python 3.10–3.13 и установку wheel. Добавляйте регрессионные тесты; при изменении семантики обновляйте все четыре руководства. Примеры должны быть синтетическими; не публикуйте частные данные. Возможное развитие: объединение профилей, фильтры путей и бюджеты динамических ключей. Лицензия MIT.
